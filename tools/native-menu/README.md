# Native graphics menus

`generate.py` derives 28 native Meme UI resources from the installed retail
`Data_hd.zip`. It creates the main-menu **Graphics Settings** entry between
Options and Profiles, Display and Advanced Graphics pages, eleven exact-value
picker pages, twelve screen titles, and a dedicated information widget and
positioned node for pages with nine rows. It never writes to the retail archive.

```powershell
python tools/native-menu/generate.py --archive game_files/Data/Data_hd.zip --header build/native_menu/mm3_menu_resources.h
python tests/mm3_native_menu_regression.py
```

The generated header exposes `MM3MenuResource`, `mm3_menu_resources` and
`MM3_MENU_RESOURCE_COUNT`. Names are relative to `Menu/Frontend/`; the runtime
resource hook serves those byte arrays at the existing native file-loader seam.
The output directory also contains the binary resources and a JSON manifest for
inspection. Generated bytes require the original native Meme type factories,
frontend namespace, locale lookup and guest function bindings.

The pages retain the retail Options page's styles, selection sounds, transitions,
controller focus, background, button help and path-stack Back action. The main
entry calls `functions/graphicsBegin` before pushing `graphics/screenGraphics`.
Setting rows push `graphics/picker<SETTING>`. Each picker shows explicit choices,
marks the current draft value with **(Selected)**, and uses the same native
Up/Down and Select controls as the original menu. Select calls a stable
`functions/graphicsSelect<SETTING><index>` binding and returns to the settings
page. Selecting the same value twice keeps that value. Merely opening a picker
or pressing Back leaves the draft intact, including custom values from the F10
panel that fall outside the listed presets.

The Resolution picker puts six common sizes on its first page, with **Other
Resolutions...** opening the remaining six. Selecting a value from that second
page uses the retail career-slides `MultiPopPathAction` with its existing count
of two to return directly to Display; its Back action returns one page. Every
other picker uses the retail single `PopPathAction` after selection. This avoids
queuing competing transitions through consecutive single pops.

The Advanced row pushes `graphics/screenAdvanced`. Back from the primary page
calls `functions/graphicsDiscard` before popping; Back from Advanced only pops.
Apply publishes and saves the complete draft; Restore Defaults prepares a draft
for Apply. Each settings row has contextual help, while Apply displays the save
status. The runtime supplies live `SID_MM3_GRAPHICS_*` labels, including picker
titles and selection markers.

The Display page's last row ends at native y324. Its information box begins at
y340 and has a height of 65 pixels, leaving a 16-pixel gap and ending at y405.
`graphics/infoBox` is a standalone copy of the retail `MmxInfoNode` resource.
The Display page and `graphics/nodeInfoBox` link to that same widget, allowing
the native loader to resolve either reference first. The native content
rectangle matches the row count on every page. The nine-choice Render Scale
picker also uses the lower help box. Advanced Graphics, the other pickers and
the remaining frontend pages retain the original help box.

`native_menu.py` preserves scalar fields while decoding sized references. A
MemeFile starts with a zero-terminated dictionary of one-byte-length ASCII
strings. Dictionary index zero contains `MemeFile 2.0`; class/name IDs begin at
one. The root starts with a little-endian 16-bit class ID. Each reference stores
an inclusive 32-bit span, a 16-bit name ID and a 16-bit class ID, followed by its
class payload. Class zero names an existing object; name/class zero is null.
Serialized references therefore recalculate every enclosing span when a node
is inserted. Scalar leaf classes remain opaque.

The established row schema is `TransformNode(next reference, four rectangle
floats, child reference)`, with child `TabstopNode(SimpleButton reference)`.
`MmxSimpleButtonNode` contains next, label, style, action and event references.
This is a sibling chain in display/focus order, so adding the Graphics Settings
row also updates the matching help list and initial selection index. The
generator validates these retail schemas and fails if its template changed.

The graph regression uses the real retail resources: unchanged round trips,
original main-menu destinations, row order and geometry, exact choice wiring,
single and multi-page returns, draft-preserving Back, contextual help, titles,
deterministic output and generated header metadata. It checks that every preset
appears once, and that the two-screen return retains the retail multi-pop payload.

`python tests/mm3_graphics_menu_regression.py` compiles the production bridge
with native allocator, constructor and namespace fixtures. It exercises all 53
registered setting choices, selected-label refresh, idempotent selection, draft
isolation, successful and failed save behavior, Defaults, Discard, custom values,
unknown-key fallback, guest register preservation and native stack cleanup.
